# xsub

Подписки, списки доменов и сторож узлов для **XKeen + Xray** на роутерах Keenetic / Netcraze.

XKeen перехватывает трафик и запускает Xray. xsub отвечает за содержимое:

- **Подписки.** Понимает почти всё, что умеет ядро Xray:
  - ссылки `vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://` (`hy2://`), `wireguard://` (`wg://`), `socks://`, `http(s)://` — списком или в base64;
  - подписки в формате **Clash / mihomo YAML**, **sing-box JSON** и **JSON Xray** (полные конфиги, как отдают Remnawave/Marzban для Happ и v2rayN);
  - транспорты TCP (в том числе с HTTP-заголовком), WebSocket, gRPC, HTTPUpgrade, XHTTP, mKCP; защита TLS и Reality; у Hysteria2 — обфускация salamander, привязка к сертификату и перебор портов.

  Узлы фильтруются по имени, информационные строки панелей («Осталось 10 ГБ» и т. п.) пропускаются. Если панель отдаёт трафик и срок действия, они видны на странице. Подписок может быть несколько.
- **Балансировщик.** Из узлов собирается `07_xsub.json`: outbounds, observatory и балансировщик `leastPing`.
- **Сторож.** Раз в минуту проверяет активный узел **реальной загрузкой** (по умолчанию 64 КБ). Это ловит блокировки, при которых короткие проверки вроде `generate_204` проходят, а настоящий трафик обрывается. Залипший узел заменяется на самый быстрый из прошедших ту же проверку. Перезапускать Xray не нужно: переключение идёт через его API.
- **Списки «Через VPN» и «Напрямую».** Редактируются на веб-странице, из них собирается `05_routing.json`. Перед применением всё проверяется через `xray -test` на копии конфигов. При ошибке ничего не меняется.
- **Geo-файлы.** Раз в сутки обновляет [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains) (`geosite_itdog.dat`): категории `russia-inside`, `youtube`, `telegram` и другие.

Один статический бинарник без зависимостей (Python не нужен). Веб-страница встроена в него.

## Требования

- Keenetic / Netcraze с Entware («Поддержка открытых пакетов»);
- [XKeen](https://github.com/jameszeroX/XKeen) с ядром **Xray** (`xkeen -xray`);
- архитектура aarch64, mipsel, mips или armv7.

## Установка

По SSH на роутере (в Entware):

```sh
curl -fsSL https://raw.githubusercontent.com/furriest/xsub/main/install.sh | sh
```

Установщик сам определит архитектуру, поставит пакет, создаст конфиг и покажет адрес веб-страницы, логин и пароль. Откройте `http://<IP-роутера>:8099/` и добавьте ссылку на подписку.

Пока подписка не добавлена, xsub не трогает конфиги Xray.

Обновление — та же команда. Если хотите обновляться через `opkg upgrade`, подключите репозиторий:

```sh
curl -fsSL https://raw.githubusercontent.com/furriest/xsub/main/install.sh | XSUB_FEED=1 sh
```

Пакет можно поставить и вручную: скачайте `xsub_<arch>.ipk` со страницы релизов и выполните `opkg install xsub_<arch>.ipk`.

## Что меняется в конфигах Xray

xsub пишет два файла в папку конфигов XKeen (`/opt/etc/xray/configs`):

| Файл | Содержимое |
|---|---|
| `05_routing.json` | правила из списков, правило для входов XKeen `force-proxy-*`, балансировщик |
| `07_xsub.json` | узлы подписок, observatory, API (`127.0.0.1:10085`), локальные входы для проверок (`127.0.0.1:10990`, `11000+`) |

`05_routing.json` полностью принадлежит xsub. Свои правила переносите в списки на странице, а не правьте файл: правки затрутся при следующем применении.

Перед первой записью исходные файлы сохраняются в `/opt/etc/xsub/backup/original/`. Вернуть всё как было:

```sh
/opt/etc/init.d/S99xsub stop
xsub -restore
```

`opkg remove xsub` делает это сам.

xsub подстраивается под существующие конфиги:
- sockopt (метку `mark`) узлы берут у `template_tag` или у первого outbound, где он задан;
- для прямого трафика используется outbound `direct` или первый `freedom`. Если их нет, xsub добавит свой;
- если в ваших файлах уже есть секции `api` или `observatory`, xsub не применит конфиг и объяснит, что поправить.

## Списки

Одна запись на строку, комментарии через `#`:

```
example.com                      # домен со всеми поддоменами
=example.com                     # только этот домен
ext:geosite_itdog.dat:youtube    # категория из файла в папке geo-файлов
geosite:telegram                 # категория из geosite.dat
1.2.3.0/24                       # IP или подсеть
regexp:^ads\.                    # регулярное выражение
```

Список «Напрямую» проверяется раньше «Через VPN». Всё, что не попало ни в один список, идёт напрямую.

Российские подсети XKeen может исключать из проксирования ещё до Xray (`xkeen -gips`).

## Настройки

`/opt/etc/xsub/config.json` (после правки: `/opt/etc/init.d/S99xsub restart`):

| Параметр | По умолчанию | |
|---|---|---|
| `listen` | `0.0.0.0:8099` | адрес веб-страницы |
| `user`, `password` | `admin`, случайный | вход на страницу |
| `sub_interval_hours` | `6` | как часто обновлять подписки (после неудачи — через 10 минут) |
| `user_agent` | `v2rayN/7.0` | панели отдают разный формат в зависимости от клиента; у каждой подписки можно задать свой |
| `max_nodes` | `60` | максимум узлов из одной подписки |
| `xray.fallback_tag` | — | ваш outbound на случай, если не работает ни один узел подписок |
| `xray.template_tag` | — | у какого outbound брать sockopt |
| `xray.restart_cmd` | `xkeen -restart` | |
| `xray.manage_api` | `true` | `false` — если API Xray уже настроен у вас (нужен `RoutingService` на `xray.api_listen`) |
| `watchdog.interval_sec` | `60` | |
| `watchdog.fails_to_switch` | `2` | сколько неудач подряд до переключения |
| `watchdog.test_url`, `test_bytes` | Cloudflare, 65536 | что качать для проверки |
| `geo.files` | itdoginfo | какие geo-файлы скачивать в `xray.assetdir` |

Подписки хранятся в `/opt/etc/xsub/subscriptions.json`, списки — в `vpn.txt` и `direct.txt` рядом. Журнал пишется в `/opt/var/log/xsub.log`.

## Безопасность

- Веб-страница закрыта паролем. Изменения принимаются только запросами с особым заголовком, поэтому чужой сайт в браузере не сможет их подделать.
- Не открывайте порт 8099 в интернет: соединение идёт по HTTP. Брандмауэр Keenetic по умолчанию входящие из интернета не пропускает.
- Ссылки подписок — секрет. Они хранятся в файлах с правами `0600` и не пишутся в журнал.

## Ограничения

Пропускаются с предупреждением то, чего нет в самом Xray:
- протоколы TUIC, Hysteria (первая версия), AnyTLS, NaiveProxy, ShadowsocksR, SSH, Mieru;
- shadowsocks с плагинами (obfs, v2ray-plugin и т. п.), VMess с `alterId > 0`;
- транспорты HTTP/2 (`h2`) и QUIC — удалены из Xray;
- цепочки прокси (`dialerProxy`) в JSON-подписках.

Особенности:
- **Проверка сертификата.** Новые версии Xray не умеют её отключать (`allowInsecure`/`insecure=1`). Такие узлы добавляются с обычной проверкой — работают, если сертификат настоящий или в ссылке есть `pinSHA256`/`pcs`.
- **Старые версии Xray.** Если установленное ядро не принимает какой-то узел, xsub пробует упрощённый вариант (для Xray до 26.10 — без перебора портов Hysteria2, прежний формат mKCP). Если не получается, отбрасывает только этот узел и пишет причину на странице, а не ломает весь конфиг.
- **WireGuard** работает в пользовательском режиме (`noKernelTun`), без создания интерфейса в системе роутера.
- Работает только с ядром Xray. Для mihomo подписки и `url-test` есть в самом ядре.

## Сборка

Зависимостей из сети нет: библиотека YAML лежит в `third_party/` (go-yaml v3.0.1, MIT/Apache-2.0).

```sh
go test ./...
VERSION=0.3.0 REPO=furriest/xsub scripts/build.sh   # → dist/
```

Релиз собирается GitHub Actions по тегу `v*`. Пакеты прикладываются к релизу, репозиторий opkg публикуется на GitHub Pages (в настройках репозитория: Pages → Source: GitHub Actions).
